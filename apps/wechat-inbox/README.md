# 拾笺 · 微信待办助手

一个基于 Tauri 2 的轻量 Windows 桌面应用。微信、模型 API、业务处理和待办去向分别管理，不依赖 OpenClaw。

> **当前处于微信纯文本接入 + 模型解析实验阶段。** 桌面端实现独立扫码、验证码、接收原始文本和保存后的回执；账号准入、独立客户端兼容性仍需用户真实扫码验证，不能把本机模拟测试当成微信实测。模型解析为实验性框架：只解析微信新消息的标题、截止日期与优先级，需要自行配置模型并显式开启；外部待办平台尚未接入。

## 已实现

- 待办、连接、设置三个页面；待办列表支持快速添加、行内完成，进行中的待办按截止日期分组。
- 本地记录新增、编辑、搜索、归档、撤销和恢复；稳定 UUID 与完整年月日。
- 完成任务与重新打开；「已完成」单独筛选。归档会记住归档前的状态（待确认/失败/已完成），恢复时原样还原；旧版本归档的记录恢复后回到待处理。
- 永久删除：确认后移除待办及其关联的提醒日志、解析任务和各状态微信回执，保留消息去重标识，避免重复投递重新创建已删除待办；归档到期自动清理遵循相同规则。导出过的文件和已经发往微信的消息不受影响，已交给网络层的在途回执无法撤回。
- 桌面提醒：今天到期或已过期且未完成的待办，通过系统通知提醒。触发方式可分别开关：解锁电脑时（每天首次解锁 / 每次解锁，默认开）、启动拾笺时（默认开）、定时重复（按小时设置间隔，如 1.5，默认关）。待办可设置具体时间（手动或由模型从“下午三点”等识别），到点单独提醒一次。解锁监听只在应用进程内接收本机当前会话的系统事件，不注册计划任务或全局钩子。
- 登录后自动启动（可选开关）：写入当前用户的启动项，关闭即移除；开启后开机第一次检查也会触发提醒。
- 记录保留策略：从归档时刻起超过保留天数后自动清除，进行中的记录不受影响。重复归档不延长期限，恢复后再归档重新起算。数据库 v6 迁移对没有归档时间的旧归档记录使用迁移时刻起算，避免升级立即删除旧记录。
- SQLite 持久化，数据位于系统应用数据目录，不操作旧 `todos.md`。
- 独立的微信二维码、验证码和连接状态；登录凭据保存在本应用的 Windows 凭据条目，不使用 OpenClaw 账号。
- 纯文本保存、按账号隔离的消息去重与持久回执队列；保存成功后才安排回执，发送失败不会重复创建记录。
- 托盘打开、暂停收发、退出；关闭窗口可选择隐藏或完全退出。普通运行只保留一个应用实例，再次启动聚焦原窗口，避免重复拉取和发送。
- 模型配置流程：填写 API 地址和密钥 → 获取模型 → 搜索选择模型和思考强度 → 保存。获取列表使用当前草稿，不要求先保存、不调用生成接口；列表不可用时可手填模型 ID。密钥留空时，只在地址与保存时一致的情况下使用已保存的密钥。
- 思考强度目前明确支持官方 DeepSeek 的 `deepseek-flash` / `deepseek-v4-pro`：服务默认、关闭、低、高、最高。其他未确认的服务/模型只使用服务默认，不发送未经确认的思考参数；旧配置仍可读取，不兼容档位会提示重新保存。
- 模型密钥保存在 Windows 凭据管理器，按规范化 API 基础地址隔离，不出现在 SQLite 或导出中。
- 原生保存对话框导出 JSON；打开本应用数据目录。
- 人工编辑与设置使用字段级更新，不回写旧快照的无关字段；后台解析以记录版本与任务领取标识校验，人工编辑、完成、归档和删除优先于迟到的模型结果。
- 模型凭据读取异常单独提示，不阻断本地待办、设置和导出。主窗口与面板合并快照刷新，订阅失败可见并支持重试；新增失败保留草稿。详情标题在 Esc、关闭、切换记录/页面/筛选及完成/归档前先保存，保存失败保留详情和草稿；永久删除经确认后可丢弃草稿。两个窗口共用截止日期、时间排序，并在本地跨午夜、窗口恢复及系统日期变化后更新日期标签，不依赖定时读取数据库。
- 模型解析（实验）：开启后，微信新消息进入解析队列，按 OpenAI 兼容 /chat/completions 请求模型输出 JSON 提议；业务层校验每个字段（日期有效性、长度、过去日期拒绝）后才写入记录，并通过微信回发解析结果。模型只能提议字段，不能执行任何其他操作；临时失败最多尝试 3 次（空对象、只有错误字段或无有效待办字段的响应也视为临时失败），永久错误直接终结并回发失败说明；模型给出非法时间或只有时间而无有效日期时，保留其余有效字段并标记待确认，不误报解析成功。记录更新、任务终结和结果回执入队原子完成。相对日期以消息时间固定参考日（缺失或无效时回退接收日）解释，跨午夜重试不漂移；处理时已过期的日期仍要求人工确认。响应体在读取过程中执行 256 KiB 上限。
- 桌面待办面板：独立小窗口常驻桌面（无边框、不进任务栏、失焦自动沉到桌面层），支持快速添加、完成/重新打开、归档与置顶（始终显示在其他窗口上面），与主窗口实时同步；主窗口侧边栏、设置和托盘菜单的开关与面板状态保持一致，位置自动记忆；可从应用设置或托盘开关。
- Windows NSIS 打包配置。

## 尚未实现

- 多轮澄清对话：解析失败时只标记“待确认”并说明缺什么，不会自动追问。
- 手动新增记录不经过模型解析（用户已经自己结构化了）。
- 图片、语音、附件和群聊处理；目前只接收绑定者的纯文本。
- 滴答清单等外部平台的账号授权和任务同步。
- 自动更新和自动清除未归档记录；进行中的记录只做手动管理。
- 任意模型协议兼容；当前只提供一种协议（OpenAI 兼容）的模型列表测试与解析调用。

“暂停收发”停止本应用的微信拉取、回执发送和在途模型解析；关闭自动识别同样取消在途解析，有效的排队任务保留以便恢复，取消不计作一次失败。本地手动记录不受影响。隐藏到托盘仍会运行；完全退出才结束本应用进程。桌面提醒依赖应用正在运行：完全退出后不会弹出提醒，开启“登录后自动启动”可保证开机后继续提醒。

## 微信连接与使用边界

1. 在桌面版“连接”页点击“连接微信”，用手机微信扫码并确认；如要求验证码，在应用中填写手机显示的数字。
2. 登录成功后，仅绑定者发来的纯文本会保存到本地收件箱，来源标为“微信记录”，原始文本保留。较长文本的列表标题可能缩短，详情保留完整的受支持文本。
3. 关闭解析时，回执只说明原始文本已保存；开启解析时先回复“正在解析”，解析完成后回发第二条结果（成功摘要或待补充原因）。解析只是字段提取，不代表任务已完成或提醒已设置；不支持的消息不得回复“已记录”。
4. “断开连接”停止本应用的收发和在途解析，清除待解析任务、回执上下文及本应用微信登录凭据；晚到解析结果不能重新创建回执。不删除本地记录，不操作其他软件的登录。重新扫码替换连接也会清理旧队列上下文。

微信请求使用腾讯 iLink 协议，不安装或运行 OpenClaw。二维码由真实服务返回的连接内容在本机生成，不展示模拟登录成功。账号是否可接入以真实服务返回为准；登录过期、验证码错误和网络故障会显示状态。暂停期间不承诺腾讯服务端无限期保留未拉取消息。

回执有持久状态和有限次数重试，但服务端是否按 `client_id` 去重不属于本地可保证的契约：网络在发送后断开时，重试可能重复回执；本地记录仍按消息标识去重。

## 开发环境

- Windows 10/11 与 WebView2 Runtime。
- Node.js 22.12+、npm。
- Rust stable、MSVC C++ 构建工具；本地验证环境为 Rust 1.94。

在本目录运行：

```powershell
npm ci
npm run desktop
```

桌面开发模式会自动启动只绑定 `127.0.0.1:1420` 的 Vite，不需要单独启动后端服务。

仅预览网页：

```powershell
npm run dev
```

浏览器预览与桌面能力明确分开：浏览器使用当前标签页的 sessionStorage，不保存密钥、不发送模型请求、不提供托盘和原生数据库。关闭标签页后预览记录可能丢失。

## 构建

```powershell
npm run desktop:build
```

正式程序嵌入前端资源，不依赖 Node.js、Vite 或本地 HTTP 服务。输出位置：

- 独立程序：`src-tauri/target/release/shijian-inbox.exe`
- 安装包：`src-tauri/target/release/bundle/nsis/`

应用尚未配置代码签名，Windows 可能显示未知发布者提示。未验证的发布者与系统安全提示不应被忽略；对外分发前应安排签名。

## 数据、凭据与卸载

- 应用标识：`dev.shijian.inbox`。
- Windows 数据目录通常为 `%APPDATA%\dev.shijian.inbox`，以应用设置中显示的实际路径为准。
- 业务数据库：该目录内的 `inbox.sqlite3`；备份时先退出应用并复制整个目录。
- 数据库 v7 为微信回执增加待办关联。升级时仅按确定性标识精确关联旧解析结果回执，并清理已无待办的旧解析回执；无法关联的旧待发送/失败回执会取消且不再补发，不删除待办或消息去重记录。旧的已发送通用确认回执无法可靠关联，保留原状、不猜测归属。迁移为事务性操作，升级前建议备份；旧版本程序不能打开已升级的数据库。
- WebView2 缓存与浏览器配置：`%LOCALAPPDATA%\dev.shijian.inbox\EBWebView`，与业务数据库分开；彻底清理前同样应退出应用。不要删除系统共享的 WebView2 Runtime。
- 模型密钥：Windows 凭据管理器中属于 `dev.shijian.inbox` 的条目，账号由规范化 API 地址计算而来。
- 微信登录：本应用的独立 Windows 凭据条目；数据库和 JSON 记录导出不包含 Bot token。队列所需的会话上下文使用当前 Windows 用户的 DPAPI 加密，不作为记录导出；换电脑不能依靠复制数据库恢复登录。
- 修改 API 地址不会把旧密钥发送到新地址；旧地址的密钥不会自动删除。可切回旧地址删除，或在 Windows 凭据管理器中检查并清理本应用条目。
- 安装版可通过 Windows“已安装的应用”卸载。当前卸载流程不承诺自动清除 AppData 或 Windows 凭据，应先导出，再确认清理自己的应用数据。
- 不注册 Windows 计划任务，也不运行独立 Node 服务。只有当你在设置中开启“登录后自动启动”时，才会写入当前用户的启动项（注册表 Run 键），关闭开关即删除；卸载不会自动移除该启动项，卸载前请先在应用内关闭。
- 没有读取旧待办、账号文件或 OpenClaw 配置。旧系统的停用、迁移、卸载应作为独立、确认后的工作进行。

## 结构

```text
src/
  App.tsx            三页界面、记录编辑、详情与确认交互
  Panel.tsx          桌面待办面板（独立窗口，?view=panel 路由）
  bridge.ts          类型化 Tauri IPC 与明确隔离的浏览器预览
  useAppSnapshot.ts  合并刷新、事件订阅、恢复与乱序保护
  types.ts           前后端数据契约
  styles.css         冷灰、沉静蓝、便笺式收件箱视觉
src-tauri/src/
  lib.rs             命令、托盘、窗口生命周期与维护循环
  parse_worker.rs    可取消解析循环与受版本/会话约束的结果提交
  database.rs        SQLite 迁移、字段更新、任务领取与原子收尾
  parser.rs          模型解析提议 → 业务校验与确定性应用
  credentials.rs     按 API 地址隔离的 Windows 凭据
  model_client.rs    受限的模型列表测试与解析调用
  session.rs         WTS 解锁事件监听（桌面提醒触发）
  wechat.rs          微信登录、收件、回执、暂停与取消
  wechat_client.rs   腾讯 iLink HTTP 协议与受信地址校验
  wechat_secrets.rs  微信专属凭据与 DPAPI 回复上下文
  validation.rs      URL、文本、日期等参数校验
```

下一阶段在已接入的微信原始文本收件链路上加入“模型理解 → 确定性业务操作 → 外部待办”。模型只提出结构化操作，实际修改必须由业务层校验并执行，不开放任意命令或文件写入。
